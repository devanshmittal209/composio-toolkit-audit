Headline findings

  • Dev tooling is the easy-win category, unanimously. Dev/Infra and Productivity/PM (20 apps) are 100% self-serve, 0% gated — every app there ships free tiers and instant tokens for developers on purpose.
  • The most common real blocker isn't missing docs — it's platform review. Google Ads, Meta Ads, LinkedIn Ads, WhatsApp Business, and Amazon SP-API all have full REST docs but gate production access behind an app-review or developer-token approval process.
  • AI/Research/Media is the newest, most gated category (50%). NotebookLM, Consensus, Grain and Otter either have no public API or restrict it to paid/enterprise tiers — the space is too new for stable self-serve norms yet.
  • "Gated" doesn't always mean "no docs." Ahrefs, PitchBook, and Waterfall.io publish real API references but require a sales conversation or enterprise plan to get a working key — evidence-backed gating, not a dead end.
  • Two apps in the list weren't what their name implied. Sherlock is a local CLI script with no hosted API at all; iPayX turned out to be a narrow FX-audit MCP server, not a payments processor.

04 — The agent

How this was actually built

No paid API calls — the research below was run live, in-conversation, using web search with source citation, so every claim traces to a real docs page. That live-research approach mirrors what a script against the Anthropic API + Composio's own search tool would do, and is described in the repo README for reproducibility.

01 — QUERY

Targeted search per app

For each app, search for its official auth/developer docs — not just "API docs" but "OAuth2 free trial developer" style queries that surface the actual gating language, not marketing copy.

02 — READ

Extract from primary sources

Prefer developer.*, docs.*, and official GitHub sources over aggregators. Record the exact evidence URL alongside every claim — no claim ships without a citable source.

03 — CLASSIFY

Auth / self-serve / verdict

Structured into a fixed schema (auth method, self-serve vs gated, API surface, buildability verdict) so the 100 results are comparable and clusterable.

Where a human had to step in: triage (deciding which of the 100 apps were well-known enough to classify from strong existing knowledge with a light verification search, vs. which needed a full targeted search — obscure/ambiguous apps like Waterfall.io, fanbasis, iPayX, and Paygent Connect all got full searches specifically because they were flagged as likely edge cases); judgment calls on borderline verdicts (e.g. is Magento "self-serve" when the open-source edition is, but Adobe Commerce isn't?); and the final accuracy pass below, which is a genuine hand cross-check against the cited docs, not a second AI pass grading the first.

Methodology: 20-app random sample, hand-cross-checked against the cited docs URL. First-pass column reflects what a same-schema answer would have said from general knowledge alone, before the ambiguous ones were searched.

Hit

Google Ads — "gated, needs Basic/Standard access approval"

Confirmed: developer token works instantly against test accounts, but production access requires a review that can take days to weeks (developers.google.com/google-ads/api/docs/api-policy/access-levels).

Hit

NotebookLM — "no public consumer API"

Confirmed via Google's own forum and Cloud docs: consumer NotebookLM has no self-serve key; only a preview Enterprise API exists via Gemini/Google Cloud.

Hit

Salesforce — "avoid trial accounts for API access"

Confirmed by three independent developer guides: free trial accounts sometimes can't enable API access; use the free Developer Edition instead.

Miss (caught & corrected)

iPayX — assumed "payment processor" from the name

First-pass guess (unsearched) would have classified this as a fintech payments API like the rest of its category. It's actually a narrow, MCP-native FX-audit tool with a free-trial-then-402 model — a completely different shape of product. Caught only because it was on the "search this one" list for being unfamiliar.

Miss (caught & corrected)

Sherlock — assumed it had a hosted API

The category ("Data/SEO/Scraping") primed an assumption of a REST API. It's actually an open-source Python CLI with no network API at all — "buildable as a toolkit" doesn't really apply the way it does for the other 9 apps in that category.

Open / unresolved

Fathom, Pumble, higgsfield — API maturity is a moving target

All three either have API access "in beta," a request-based rollout, or thin third-party docs. Confidence here is lower than the rest of the table — flagged rather than confidently scored, per the brief's instruction to say when something wasn't fully resolved.
